# 03. Проверка без Raspberry Pi

У наблюдателя нет ничего специфичного для Pi: он общается только с IPC-сокетом
mpv. Поэтому «заглушка» здесь — обычный mpv на рабочем столе, а пути к
файлу и сокету в `config/dev.toml` указывают в `./dev-data` (он в `.gitignore`).

## Вручную

```sh
mkdir -p dev-data
mpv --idle=yes --force-window=yes --input-ipc-server=dev-data/mpv.sock &
RUST_LOG=debug cargo run -- --config config/dev.toml
```

Что стоит посмотреть:

1. `socat - UNIX-CONNECT:dev-data/state.sock` — без запроса ничего не
   приходит. Наберите `status`: виден режим файла (`read-write`).
2. Перетащить файл в окно mpv → `last` сразу знает его, `dev-data/state.json`
   появился.
3. Пауза, громкость, перемотка → файл переписывается сразу (`sequence` растёт).
   Просто воспроизведение → не чаще раза в `position-save-seconds`. Пауза →
   записи прекращаются.
4. Закрыть mpv и запустить новый (пустой) → `last` по-прежнему показывает
   старый pid и файл, `get` — новый пустой mpv.
5. Остановить наблюдатель (Ctrl+C) и запустить снова → `last` сразу известен:
   он загружен из файла.
6. Режим «только для чтения»: указать `state-file` в каталоге без права
   записи — например, `chmod 500` для обычного пользователя или
   `mount --bind -o ro` от root. В `status` будет `read-only` с причиной, а
   после перезапуска `last` ответит `"known": false`, даже если старый файл
   там лежит.
7. Ctrl+C → `state.sock` исчезает.

## Вместе с REST-сервисом

В dev-конфиге REST-сервиса mpv запускает сам сервис (его сокет —
`../remoteplayer-restservice/dev-data/run/mpv.sock`), а восстановление он
берёт из `restore.watcher-socket`
(`../remoteplayer-restservice/dev-data/watcher/state.sock`). Укажите эти пути
в `mpv-socket` и `state-socket` наблюдателя. Тогда:

- `kill -9` процесса mpv → супервизор REST-сервиса через 3 секунды поднимет
  mpv, сервис увидит новый пустой mpv и восстановит воспроизведение по `last`;
- остановить оба сервиса и запустить снова (сначала наблюдатель) — это
  имитация перезагрузки: REST-сервис при старте восстановит снимок из файла
  наблюдателя.

## Юнит-тесты

`cargo test` — без mpv. В `src/mpv_connection.rs` есть `serve_fake_mpv`:
маленький сервер на `UnixListener`. Он отвечает на `get_property` из
словаря, на `observe_property` присылает начальное событие, как настоящий
mpv, а перед каждым ответом шлёт постороннее событие, чтобы проверить, что
клиент его пропускает. Он же считает запросы: тест `sampler.rs` проверяет, что
`get` каждый раз идёт в mpv. Тест `tracker.rs` запускает трекер против этого
сервера и проверяет, что `last` наполняется из событий, а при остановке
снимок оказывается в файле. Тесты сокета проверяют, что без запроса сервер
молчит, а на `get`, `last`, `status` и неизвестную команду отвечает одной
строкой.
Остальное — чистая логика (`recorder.rs`) и временные каталоги
(`tempfile`) для файла и сокета.
